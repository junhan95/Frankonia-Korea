## 1. 수집 방법과 결과

이미지 URL은 페이지 HTML에서 직접 뽑았다. 지연 로딩이라 `<img src>`만 보면 절반을
놓친다 — `srcset`·`href`(라이트박스)·`content`(og:image)까지 훑어야 전부 나온다.
WordPress `-1800x1024` 류 접미사는 축소본이므로 **접미사를 떼어 원본**을 받았다.

| | |

| md5 고유 | 98건 |
| 원본 총량 | 211 MB (최대 3680×2456 · 6.6 MB) |
| 변환 후 | **98개 파일 · 14 MB** |

변환 — `sharp`, webp, **업스케일 없음**(`withoutEnlargement`).

- 정사각 원본(1400×1400 · 2500×2500)은 본사의 **흰 배경 절개 렌더**다. 도판이 아니라
  카드에 들어가므로 900px 상자.
- 그 외는 1600px 상자, quality 82.
- 압축이 듣지 않는 네 장은 상자와 quality를 낮춰 다시 인코딩했다
  (`shielded-room-6` 760px/q68 · `mil-std-chamber-advanced-4` 1200px/q72 ·
  `sac-3-square-2` 1100px/q76 · 그 외 세로 사진 q74~76).
  `shielded-room-6`은 오래된 아카이브 사진이라 화면 노이즈가 많다 — 223 KB가 한계다.

이름은 `<모델 슬러그>-<n>.webp`. **`-0`은 본사 포트폴리오 카드 이미지**(대개 절개 렌더),
`-1` 이후가 실제 촬영 사진이다. 페이지 등장 순서를 그대로 쓴 것이라, 나중에 원본과

## 6. 모델 갤러리 (Phase C, 2026-08-13)

모델 목록의 행이 펼쳐지면서 **모델당 사진 2~3장의 갤러리**가 필요해졌다.
§5에서 지운 72장을 다시 받은 것이 이 수집이다.

### 다시 받은 방법

§1과 같다 — 모델 페이지 26개를 다시 긁어 `src`·`srcset`·라이트박스 `href`·`og:image`를
훑고, WordPress `-1800x1024` 류 접미사를 떼어 원본을 받았다. **125장**이 나왔다
(2026-08-11의 98장보다 많다. 본사가 그 사이 사진을 더 올렸다).
긴 변 중앙값 2,500px · 최대 6,720px.

번호는 §2와 그대로 맞는다. 기존 26장을 16×16 그레이스케일 지문으로 대조해 확인했고,
전부 점수 2~4 대 차순위 23~75로 일치가 명확했다. 그래서 새 파일도 `<슬러그>-<n>.webp`
규칙을 이어 쓴다.

### 다른 소스는 왜 안 썼나

사용자 요청으로 셋을 다시 확인했다. 결론은 §4와 같다.

| 소스 | 장수 | 긴 변 | 모델 매핑 |
|---|--:|---|---|
| **본사 웹** | 125 | 중앙값 2,500 · 최대 6,720 | **페이지=모델, 이미 되어 있음** |
| `Frankonia Anechoic Chambers 2026.pdf` | 105 | 150 ppi, 대부분 350~1,122 | 스프레드 단위 |
| `Frankonia Photobook 2026.pdf` | 65 | 최대 2,009×1,241 | 없음. 분위기 사진 위주 |
| `Frankonia Anechoic Chamber Solutions.pptx` | 212 | 중앙값 1,092 (1600+ 는 61장) | 없음. 슬라이드 수작업 |

PPTX의 1600px 이상 61장은 **남는 후보**다. 랜딩·기술 토픽용 대형 사진이 필요해지면
(`chambers-assets.md` §3의 "채우지 못한 자리") 여기가 다음 순번이다.

### 걸러낸 것

- **어두운 배경 사진 26장** — 26개 모델 페이지 전부에 같은 파일이 들어 있다.
  모델 사진이 아니라 사이트 공용 배경이다. 교차 지문 대조로 찾아냈다.
- `ctc/00` — `actc/00`과 동일. §3이 2026-08-11에 이미 기록한 재사용 건이고,
  이번에도 같은 판단으로 뺐다.
- `sac-10-plus/00` == `triton/00` — 두 모델이 셸을 공유해 렌더가 같다.
  SAC-10 Plus 쪽에만 남겼다. Triton은 사람이 들어간 `triton-4`와 `triton-3`이 있어
  아쉽지 않다.

### 고른 것 — 모델당 2장 (48장 · 5.3 MB)

§5와 같이 **컨택트시트를 만들어 26장 전부 눈으로 보고** 골랐다. 기준도 같다:
그 모델이 다른 모델과 갈라지는 지점을 보여 주는가. 여기에 하나 더 —
**세 장이 서로 다른 것을 말하는가**. 대개 절개 렌더(구조) + 사진(현장)의 짝이다.

**4개 모델은 1장뿐이다** — MIL CHC · MIL-STD Chamber · EDTC-AX · EDTC-BB.
본사가 각 3장을 올려 두었고 그중 하나가 이미 쓰는 도판, 하나가 공용 배경이다.
갤러리 2장이 소스가 허락하는 전부이고, 세 번째를 만들어 넣으면 그건 이 챔버가
아닌 사진이 된다.

변환 — `sharp`, webp, q80, 긴 변 1400px 상자, **업스케일 없음**. 도판이 1600px인
것과 달리 1400px인 이유는 패널에서 약 410 CSS px로 읽히고, 갤러리는 한 페이지가
한 장이던 자리를 세 장이 차지하기 때문이다.
`shielded-room-6`만 1000px/q70으로 다시 인코딩했다 — 벌집 패널이라 압축이 듣지
않아 292 KB였다.

절개 렌더의 **흰 배경 문제**(§5가 열어 둔 것)는 갤러리 상자 자체를 흰색으로
칠해 해결했다. 렌더는 배경과 이어지고 사진은 흰 여백을 두른다.
`object-fit`은 `contain` — 두 번째 사진의 요점이 가장자리에 있는 경우가 많아
잘라내지 않는다.

alt는 `app/chamber-gallery.ts`에 로케일별로 들어 있다. 규칙은 §5와 같다 —
**사진에 실제로 보이는 것만**. 절개 렌더는 렌더라고 밝혀 적었다. 그러지 않으면
보지 못하는 사람에게 벽이 세 면뿐인 방을 설명하는 셈이 된다.
